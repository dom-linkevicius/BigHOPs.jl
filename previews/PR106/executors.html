Executors ​

Executors are the workhorses of BigHOPs.jl, they specify how the individual trials are run, launch new ones when necessary. The executor has to be specified when run! is called on a Hyperoptimizer, with the conscious goal for flexibility and modularity, to be able to run any sampler with any executor:

julia
ho = Hyperoptimizer(f, domains; sampler=RandomSampler(), n=100)
run!(ho; executor=Threaded())

The choice of executor should be informed by the problem at hand. Pick Serial for development and debugging, Threaded for one machine with multiple cores and intermediate size problems, and DistributedQueue for clusters, or trials that need a process of their own or a time limit. Finally, see General functionalities for some additional convenience functionalities related to executors.

Serial ​

BigHOPs.Serial Type
julia
Serial()

Evaluate trials one at a time, in the calling task.

source

Serial is the default for run!. It is the simplest to debug, suits objectives that already use every core of the machine on their own.

Threaded ​

BigHOPs.Threaded Type
julia
Threaded(max_concurrency=Threads.nthreads())

Evaluate up to max_concurrency trials at once, as tasks spread over Julia's threads. Start Julia with --threads=N for real parallelism; on one thread the trials only interleave.

source

The objectives evaluated using Threaded have to be safe to run many trials concurrently, for example by not writing to shared global state (BigHOPs.jl does not ensure this, therefore it is left for the user).

DistributedQueue ​

BigHOPs.DistributedQueue Type
julia
DistributedQueue(max_concurrency=Sys.CPU_THREADS; spawn_worker,
                 setup_worker=Returns(nothing), teardown_timeout=30,
                 max_single_runtime=Inf, worker_metadata=Returns(NamedTuple()))

Evaluate each trial on its own freshly spawned Distributed worker, up to max_concurrency at a time, removing the worker when the trial returns. Suited to clusters, where spawn_worker can request a process from a scheduler.

  • spawn_worker(): start one worker and return its process id, e.g. () -> first(addprocs(1)).

  • setup_worker(pid): prepare that worker before its trial, e.g. load packages and define the objective there.

  • teardown_timeout: seconds to wait when removing a worker.

  • max_single_runtime: seconds a trial's objective may run before its worker is killed and the trial marked TimedOut; the default Inf sets no limit. Also accepts a function of the trial's parameters, e.g. x -> 30 + 20 * x.r to scale with a successive-halving resource level; if it throws or returns a non-positive limit, that trial fails.

  • worker_metadata(): run on each trial's worker before its objective, returning a NamedTuple of extra details to record, e.g. () -> (job = ENV["SLURM_JOB_ID"],). They are stored as text in the trial's metadata[:worker], alongside the worker id, host, OS process id and start time; if it fails, the trial runs without them and the error is recorded as metadata_recording_error.

source

Each worker is a fresh Julia process, so the objective has to be defined there. A convenient pattern is to keep it in its own file and include that file both locally and in setup_worker:

julia
using Distributed
using BigHOPs

include("objective.jl")  # defines `f(x)`

spawn_worker() = first(addprocs(1; exeflags="--threads=12"))
function setup_worker(pid)
    remotecall_eval(Main, [pid], :(using BigHOPs; include("objective.jl")))
    return nothing
end

ho = Hyperoptimizer(f, domains; sampler=SobolSampler(), n=200)
run!(ho; executor=DistributedQueue(8; spawn_worker, setup_worker, max_single_runtime=3600))

The option to spawn and kill processes instead of having one process with a large resource pool was due to various factors, e.g. trials freezing, processes dying and resources being unrecoverable, efficiency of resource usage in cases where initially a sampler can benefit from lots of processes, but only runs few at the end.
