Domains ​

The high-level problem being solved in BigHOPs.jl is hyperparameter optimization. Letting be the hyperparameters of a model and be the objective value with these parameters, we want to solve a minimization problem . Therefore, the initial step is to define the search space for the candidate values of (for now we omit how the candidates are sampled and how the objective is executed).

In BigHOPs.jl this candidate space is defined using a NamedTuple, with one entry per hyperparameter, and passed to the Hyperoptimizer. Using neural network training as a loose inspiration, an example of domains could be:

julia
domains = (
    lr=Continuous(-4, -1; transform=exp10), # learning rate
    n_layers=Ordinal(1:3),                  # depth of network
    width=Ordinal([8, 16, 32, 64]),         # width of network
    activation=Nominal([tanh, abs]),        # activation functions
)
ho = Hyperoptimizer(f, domains, ...)

The objective f is evaluated by passing the sampled candidate values as a NamedTuple with instances from the domains specified in domains, e.g. x.lr, x.width and so on. Under the hood each domain (including Ordinal and Nominal) is sampled from a unit interval with the domains specifying the transformations which take the sampled values to their natural domain. This allows for a unified candidate representation, overriding it only when a sampler requires it (see BOHB). BigHOPs.jl has three types of domains.

Continuous ​

BigHOPs.Continuous Type
julia
Continuous(min, max; transform=identity)

A real interval [min, max], passed through transform after sampling, so Continuous(-4, -1; transform=exp10) is log-uniform over [1e-4, 1e-1]. transform must be finite at both ends, and should be a named function rather than a closure if the optimizer will be checkpointed.

source

The transform makes it easy to specify hyperparameters that span orders of magnitude, such as learning rates or regularization strengths, which are best searched on a log scale.

Ordinal ​

BigHOPs.Ordinal Type
julia
Ordinal(levels::Int)
Ordinal(values::AbstractVector)

An ordered set of choices. Numeric values must be sorted ascending; non-numeric values are taken in the order given, with a warning. Ordinal(k) is shorthand for the choices 1:k. It is also the domain for integer hyperparameters, e.g. Ordinal(1:10).

source

Nominal ​

BigHOPs.Nominal Type
julia
Nominal(levels::Int)
Nominal(values::AbstractVector)

An unordered set of choices, of any type, including functions. Nominal(k) is shorthand for the choices 1:k.

source

The Nominal domain should be used when the choices have no intrinsic order, such as activation functions, optimizers or model architectures. The values can be anything, so the objective can use them directly, e.g. x.activation.(y) where y is some vector. In most cases Nominal behaves identically to Ordinal, except for the BOHB sampler, where a different kernel has to be used (see BOHB).
